# Contributing

Thanks for helping improve this learning portfolio.

1. Open an issue describing the bug or proposed improvement.
2. Create a focused branch for your change.
3. Use clear notebook titles and explain non-obvious steps in Markdown.
4. Keep examples reproducible where practical by setting random seeds.
5. Run `make check` (or `ruff check src tests examples apps api scripts`, `python -m pytest -q` and `python scripts/check_notebooks.py`) before opening a pull request.
6. Do not commit secrets, private data, generated model artifacts, or datasets without checking their license.

Pull requests should explain what changed, how it was tested, and whether notebook outputs or images need updating.
